프론트엔드 핵심 UI 용어 TOP 30 도감

프론트엔드 개발 시 자주 사용하는 핵심 UI 구성 요소의 정의, 활용 방법, 그리고 HTML/CSS/JS로 실제 구현된 인터랙티브 예제를 제공합니다.

01

Button

Input / Action

버튼

사용자가 클릭하여 액션(폼 제출, 모달 열기, 페이지 전환 등)을 유발하는 가장 대표적인 입력 컨트롤입니다. 호버, 액티브, 포커스, 비활성화(disabled), 로딩 중 상태 등을 세심하게 디자인해야 합니다.

02

Input

Input / Form

입력창

텍스트, 숫자, 비밀번호 등을 사용자로부터 직접 입력받는 창입니다. 라벨(Label), 플레이스홀더(Placeholder), 도움말 텍스트(Helper Text), 에러 상태에 따른 필드 변형 등이 고려되어야 합니다.

실시간 예제 (Live Demo)

영문 소문자, 숫자 조합 4~12자 유효하지 않은 입력입니다.
03

Checkbox

Input / Form

체크박스

여러 옵션 목록 중에서 복수의 항목을 동시에 선택할 수 있도록 해주는 입력 필드입니다. 선택(Checked), 해제(Unchecked), 부분 선택(Indeterminate) 및 비활성화 상태를 표현할 수 있습니다.

04

Radio Button

Input / Form

제시된 여러 옵션 중에서 오직 한 가지만 강제하여 선택할 수 있도록 해주는 UI 요소입니다. 동일한 `name` 어트리뷰트 속성으로 묶어 브라우저가 다중 선택을 배제하게 동작시킵니다.

1. 코드 저장소 (Git)

  • GitHub

    코드 저장, 버전 관리, 협업과 오픈소스 참여에 사용하는 대표 플랫폼

    기업 프로젝트와 CI/CD 기능에 강한 Git 플랫폼

2. 배포 (Hosting)

  • Vercel

Chapter 03 · 인터넷 기초

인터넷에서 웹페이지는 어떻게 찾아올까?

웹사이트를 여는 과정은 전화로 가게에 주문하는 것과 비슷합니다. 주소를 찾고, 원하는 것을 말하면, 가게가 결과를 보내줍니다.

  • 내 컴퓨터와 서버 구분하기
  • 인터넷 주소 읽기
  • 요청과 답변 이해하기
  • 화면과 내부 작업 구분하기

1. 웹사이트를 여는 과정

네이버나 유튜브 주소를 입력했다고 생각해 보세요. 아래 네 단계를 거쳐 화면이 나타납니다.

① URL 입력웹 주소 입력
② DNS 조회서버의 IP 주소 찾기
③ HTTP 요청서버에 자료 요청
④ HTTP 응답HTML·CSS·JS 받기

2. 등장인물 알아보기

어려운 이름도 역할을 일상생활에 빗대면 쉽게 이해할 수 있습니다.

클라이언트 (Client)

서비스를 요청하는 브라우저나 앱입니다. 쉽게 말해 가게에 주문하는 손님입니다.

서버 (Server)

요청을 처리하고 결과를 보내주는 컴퓨터입니다. 주문을 받아 처리하는 가게와 같습니다.

DNS (Domain Name System)

naver.com 같은 도메인 이름을 IP 주소로 바꿔줍니다. 인터넷의 전화번호부 역할입니다.

데이터베이스 (Database)

회원, 글, 사진과 주문 내역을 체계적으로 저장하는 곳입니다. 서비스의 자료 창고와 같습니다.

3. URL은 인터넷 주소입니다

네이버에서 “웹개발”을 검색하면 아래와 같은 실제 주소가 만들어집니다. 어느 사이트에서 어떤 기능을 사용했고 무엇을 검색했는지가 URL에 담겨 있습니다.

https://search.naver.com/search.naver?query=웹개발

프로토콜 (Protocol)

https://는 네이버 서버와 안전하게 통신하겠다는 규칙입니다.

도메인 (Domain)

search.naver.com은 네이버의 검색 서버를 가리키는 이름입니다.

경로 (Path)

/search.naver는 네이버 서버에서 검색 기능을 담당하는 위치입니다.

쿼리 스트링 (Query String)

?query=웹개발은 query라는 항목에 검색어 “웹개발”을 담아 서버로 전달합니다. 한글은 브라우저에서 %EC%9B%B9...처럼 표시될 수도 있습니다.

4. HTTP는 대화 규칙입니다

사람들이 인사말과 문장 규칙을 사용하듯, 브라우저와 서버도 HTTP라는 약속에 맞춰 대화합니다.

요청 (Request)

브라우저: “3번 강의 내용을 보여주세요.”

응답 (Response)

서버: “네, 찾았습니다. 여기 있습니다.”
200 잘 처리했어요201 새로 만들었어요400 요청을 이해하기 어려워요401 로그인이 필요해요404 찾는 것이 없어요500 서버에 문제가 생겼어요

5. 프론트엔드와 백엔드

식당으로 비유하면 프론트엔드는 손님이 보는 홀이고, 백엔드는 음식이 만들어지는 주방입니다.

프론트엔드 (Frontend)

사용자가 직접 보는 화면입니다. 식당의 홀처럼 버튼, 메뉴, 글자와 이미지를 보여줍니다.

백엔드 (Backend)

로그인, 계산과 자료 저장을 화면 뒤에서 처리합니다. 음식이 만들어지는 주방과 같습니다.

6. 핵심 용어 정리

비유를 이해했다면 이제 실제 개발에서 사용하는 이름을 함께 기억해 두세요.

클라이언트 (Client)
서버에 정보나 기능을 요청하는 브라우저 또는 앱
서버 (Server)
클라이언트의 요청을 처리하고 결과를 보내주는 컴퓨터
DNS
도메인 이름을 IP 주소로 바꿔주는 시스템
IP 주소 (IP Address)
인터넷에 연결된 컴퓨터를 구분하는 숫자 주소
URL
인터넷에서 페이지나 자료의 위치를 나타내는 전체 주소
도메인 (Domain)
naver.com처럼 사람이 읽기 쉽게 만든 사이트 이름
경로 (Path)
사이트 안에서 특정 페이지나 자료가 있는 위치
쿼리 스트링 (Query String)
URL의 ? 뒤에 붙여 서버에 전달하는 추가 조건
HTTP
브라우저와 서버가 요청과 응답을 주고받는 통신 규칙
상태 코드 (Status Code)
200, 404, 500처럼 처리 결과를 알려주는 숫자

학습 확인

정확한 용어를 외우기보다 아래 내용을 일상적인 말로 설명할 수 있으면 충분합니다.

  • 서버를 “주문을 처리하는 가게”라고 설명할 수 있나요?
  • DNS를 “인터넷 전화번호부”라고 설명할 수 있나요?
  • 404가 “찾는 페이지가 없다”는 뜻임을 알고 있나요?
  • 프론트엔드는 화면, 백엔드는 화면 뒤의 처리라는 차이를 알고 있나요?

Chapter 05 · Version Control

Git과 GitHub로 변경 이력 관리하기

Git은 파일을 언제, 왜, 어떻게 바꿨는지 기록합니다. 보고서의 “최종본”, “진짜 최종본”을 여러 개 만드는 대신 변경 과정을 차곡차곡 저장하는 도구입니다.

  • Git과 GitHub 구분
  • 핵심 용어 이해
  • add·commit·push 흐름
  • 보안 정보 제외하기

1. Git은 왜 필요할까?

파일을 잘못 수정했거나 여러 사람이 동시에 작업할 때, 변경 기록을 이용하면 이전 상태로 돌아가거나 작업 내용을 합칠 수 있습니다.

변경 기록

누가 언제 어떤 내용을 바꿨는지 확인합니다.

이전 상태 복구

문제가 생기기 전의 정상적인 코드로 돌아갈 수 있습니다.

협업

여러 사람의 작업을 비교하고 하나의 프로젝트로 합칩니다.

실험 공간

기존 코드를 지키면서 새로운 기능을 별도로 개발할 수 있습니다.

2. Git과 GitHub의 차이

Git은 기록 도구이고 GitHub는 그 기록을 공유하는 온라인 공간입니다.

Git

내 컴퓨터에서 파일의 변경 이력을 기록하는 버전 관리 프로그램입니다. 인터넷이 없어도 사용할 수 있습니다.

GitHub

Git으로 기록한 프로젝트를 인터넷에 저장하고 다른 사람과 공유하는 온라인 서비스입니다.

3. 반드시 알아야 할 용어

저장소 (Repository)
프로젝트 파일과 변경 기록을 함께 보관하는 공간
커밋 (Commit)
현재 변경 내용을 설명과 함께 하나의 기록으로 저장하는 것
브랜치 (Branch)
기존 작업에 영향을 주지 않고 별도로 개발하는 작업 갈래
병합 (Merge)
서로 다른 브랜치의 변경 내용을 하나로 합치는 것
원격 저장소 (Remote)
GitHub처럼 인터넷에 있는 저장소
복제 (Clone)
원격 저장소의 프로젝트와 기록을 내 컴퓨터로 가져오는 것

4. 기본 작업 흐름

파일을 수정한 뒤 바로 GitHub로 보내는 것이 아닙니다. 선택하고, 기록하고, 전송하는 세 단계를 거칩니다.

파일 수정작업 공간
git add기록할 변경 선택
git commit내 컴퓨터에 기록
git pushGitHub로 전송
  Terminal
$ git status
$ git add index.html
$ git commit -m "강의 페이지 추가"
$ git push origin main

Chapter 06 · Deployment

내 웹사이트를 인터넷에 공개하기

내 컴퓨터에서만 보이던 웹사이트를 다른 사람도 주소로 접속할 수 있게 만드는 과정을 배포(Deployment)라고 합니다.

  • 로컬과 배포 구분
  • 빌드와 호스팅 이해
  • 도메인·DNS·HTTPS 이해
  • 환경 변수 안전하게 관리

1. 배포란 무엇일까?

작성한 파일을 24시간 인터넷에 연결된 서버에 올리고, 누구나 URL로 찾아올 수 있게 만드는 일입니다.

로컬 환경 (Local)

localhost처럼 내 컴퓨터에서만 확인할 수 있는 개발 상태입니다.

배포 환경 (Production)

인터넷 주소를 통해 다른 사람도 접속할 수 있는 실제 서비스 상태입니다.

2. 배포에 필요한 기본 용어

배포 (Deployment)
완성한 프로그램을 사용자가 접속할 수 있는 서버에 공개하는 과정
빌드 (Build)
개발용 코드를 브라우저나 서버가 실행하기 좋은 결과물로 만드는 과정
호스팅 (Hosting)
웹사이트 파일이나 서버 프로그램을 인터넷에 연결된 컴퓨터에서 운영하는 서비스
프로덕션 (Production)
실제 사용자가 이용하는 운영 환경
도메인 (Domain)
example.com처럼 사용자가 입력하는 웹사이트 이름
DNS
도메인을 실제 서버의 IP 주소와 연결하는 시스템
HTTPS
브라우저와 서버가 주고받는 내용을 암호화하는 안전한 통신 방식
CDN
여러 지역의 서버에서 파일을 전달해 웹사이트를 빠르게 보여주는 네트워크

Chapter 07 · API Practice

NASA API로 오늘의 우주 사진 가져오기

직접 발급받은 API 키를 요청 URL에 넣고, NASA 서버가 보내준 JSON 데이터를 사진 카드로 표시합니다.

  • API 키 발급
  • 엔드포인트 이해
  • fetch와 JSON 사용
  • 로딩·오류 처리

1. API와 API 키

API는 다른 서비스의 기능이나 데이터를 정해진 방법으로 요청하는 창구입니다. API 키는 누가 요청했는지 구분하는 발급 번호입니다.

API = 주문 창구

NASA가 정한 주소와 규칙에 맞춰 사진 데이터를 요청합니다.

API 키 = 이용자 번호

NASA가 요청한 사람과 사용량을 구분하기 위해 발급하는 문자열입니다.

2. NASA API 키 발급하기

  1. NASA Open APIs 페이지를 엽니다.
  2. Generate API Key 영역에 이름과 이메일을 입력합니다.
  3. 발급된 키를 복사해 안전한 곳에 보관합니다.
  4. 아래 실습 입력란에 키를 붙여 넣습니다. 이 페이지는 키를 저장하지 않습니다.

3. 요청 URL 읽기

엔드포인트(Endpoint)는 API 요청을 받는 정확한 인터넷 주소입니다. 쿼리 스트링으로 API 키와 날짜를 전달합니다.

https://api.nasa.gov/planetary/apod?api_key=발급받은_키&date=2026-06-23
Endpoint
/planetary/apod — 오늘의 천문 사진을 요청하는 기능
api_key
NASA에서 발급받은 이용자 식별 키
date
YYYY-MM-DD 형식으로 지정하는 사진 날짜

4. 실시간 API 실습

API 키와 날짜를 입력한 뒤 요청 버튼을 누르세요. 요청은 NASA 서버로 직접 전송되며 키는 브라우저에 저장되지 않습니다.

아직 요청하지 않았습니다API 키와 날짜를 입력해 우주 사진을 불러오세요.

5. JavaScript 코드 이해하기

JavaScript
const response = await fetch(url);
const data = await response.json();

title.textContent = data.title;
image.src = data.url;
description.textContent = data.explanation;

fetch(url)

지정한 API 주소로 HTTP 요청을 보냅니다.

response.json()

서버가 보낸 JSON 문자열을 JavaScript 객체로 바꿉니다.

await

서버의 응답이 도착할 때까지 해당 작업의 완료를 기다립니다.

data.title

JSON 객체에서 title이라는 이름의 값을 꺼냅니다.

API 요청에 성공하면 실제 JSON 응답이 아래에 표시됩니다. 개발자 도구의 Network 패널에서도 같은 응답을 확인할 수 있습니다.

7. API 키 보안

이 실습은 API 요청 원리를 배우기 위한 로컬 실습입니다.
실제 공개 서비스의 프론트엔드 코드에 비밀 API 키를 넣으면 개발자 도구에서 누구나 볼 수 있습니다. 운영 환경에서는 서버 또는 서버리스 함수가 키를 보관하고 대신 NASA API를 호출해야 합니다.
  • API 키를 GitHub에 커밋하지 않습니다.
  • 키는 .env와 배포 서비스의 환경 변수에 저장합니다.
  • 키가 노출되었다면 기존 키를 폐기하고 새 키를 발급받습니다.
